# Phase 0 port survey: upstream sharpemu/sharpemu pull requests

Date: 2026-10-18. Scope: research only, no code changed. Upstream tip surveyed: `upstream/main` = 8bb85e09d (already fully merged into our `main`; `git rev-list main..upstream/main` = 0).
Data: 949 PRs listed with `gh pr list --state all` (479 merged, 391 closed unmerged, 79 open of which 12 are drafts). Helper data (PR JSON, diffs, per-PR file lists, `git apply --check` results against our tree) was kept in `/tmp/ps` and is not part of the repo.
Licensing: upstream and this fork are GPL-2.0-or-later, so direct ports are fine. One exception found: `Atrac9DecodeState.cs` inside #1097 is marked `GPL-2.0-only` (adapted from YoteiPC); do not take it.

## Key findings

1. **There are no merged upstream PRs missing from our main.** Every merge commit of a merged PR that exists in the object store is an ancestor of `main`. The only "merged but absent from our tree" content is what upstream itself reverted: the 18 rendering/perf PRs reverted by #1065 (#1024, #1025, #1031-#1041, #1051, #1054, #1055, #1058, #1059; re-proposed as open #1066), the Ghost of Yōtei commit `c7bbb0931` (#926, reverted by `3f84f5906`; re-proposed as open #1097), and #1086 (reverted by #1091). The #1065 revert was a process revert (to re-review as one PR), not a regression fix. The #926 revert was for DS/Astro Bot vertex explosions and audio crackling.
2. **Our tree diverges structurally.** The upstream Vulkan GPU code was moved to `src/graphics/SharpEmu.Gpu.Vulkan/`; our renderer is Metal V2. Upstream's "Alpha Rebuild" (#887, 2026-09-19) rewrote AGC, the shader compiler and the Gen5 command path, so most PRs numbered below ~887 target code that no longer exists. Textual `git apply` fails for almost every shared-code PR; ports are semantic re-implementations, not cherry-picks.
3. **Much of the useful upstream work is already in the fork**, either as merged PRs (#913, #955, #1000, #1013, #1028, #1029, #1082 ... all >85% of added lines present in main) or as `[Upstream #N]` commits (#884, #819, #877, #697, #586, #588, #703, #792, #801, #815, #849, #883 are in). Verified present in Metal: all shader opcodes in the open ALU PRs (#863, #854, #784), pixel interpolant mapping, rect-list/NGG, indirect draws, COND_EXEC, rewind/jump, DS-relevant stencil handling, NGG-to-mesh (`Gen5MslTranslator.Mesh.cs`, ahead of #1061's Vulkan-only native mesh path).
4. **Group E result:** all 184 compiled Demon's Souls shader listings (`artifacts/msl-ds*`, ~132k instructions) translate; the only decoder opcodes Metal lacks are `VSadU8`, `VSadHiU8`, `VSadU16`, none used by DS. Opcode-coverage PRs are not worth time for DS.
5. **PRs authored by xnetcat (74 closed, #1103 draft, #1066, #1060, #1042) and juanfariasdev's #956-#999 are the fork's own lineage**; they were checked for already-in-fork status rather than treated as new work. #1103 is our fork's perf work offered upstream.
6. **Ghost of Yōtei PR = #1097** ("[WIP] Ghost of Yōtei / Tsushima", foufouadi, open, not merge-ready, 33 commits on top of the re-landed #926, 35.5k added lines). Its predecessor #926 was merged then reverted; #1057 and #1007 (MathiasYG Tsushima drafts) are closed. Almost all of its bulk is Vulkan-only (buffer/image caches, tessellation, render scale, mixed-sample); the portable value is a handful of shader-compiler / HTile / loader items listed below.
7. **#1074** (draft, par274, "Precompiled shaders probe") is the only upstream work aimed directly at shader-compile stutter and first-run cost; see rank 4.

## Notes on the top 15

**1. #1051, flip ordering (S).** `sceVideoOutSubmitFlip` reserves its request as `Pending` before it is queued; an earlier command buffer that waits in `sceAgcDcbWaitUntilSafeForRendering` on the same buffer then sees the pending flip as "not done", while the flip's preparation sits behind that command buffer. Port: add `FlipRequest.Ordered` (set from `gpuQueued`) and `MarkFlipOrdered(requestId)`; make `IsFlipDone` require `Ordered`; call `MarkFlipOrdered` from `MetalCommandStream.PrepareCpuFlip` (line ~1471) and `MetalCommandStreamHost.PrepareCpuFlip` (~232). The wait site is shared (`GpuCommandInterpreter.Labels.cs:546`). Skip the Rosetta GC re-exec in the same PR (we set `GCgen0size=64MB` in the bundle already, and it is moot after ARM64). The movie watchdog part is already in via #1101.

**2. #1031, lock contention (M).** Port in pieces. (a) `TryAcquireContinuationStub`/`ProtectContinuationStub`: `[ThreadStatic]` stubs per nesting depth reopened with a direct `mprotect`, replacing the per-resume 512-byte VirtualAlloc/free in `ExecuteGuestContinuationEntry` (`DirectExecutionBackend.cs:6599-6625`); caveat: a direct mprotect bypasses `MacHostMemory`'s shadow table, so check the fault bridge and diagnostics do not query that page. (b) `[ThreadStatic] _registeredExternalHandle/Context` early-out in `RegisterGuestThreadContext` (`:4028`), about 10 lines. (c) Replace the `usleep` Sleep stubs (`MacHostStubs.cs:328`, `MacOSExecutionStubs.cs:247`; duplicated) with `nanosleep` resumed on EINTR. (d) Lock-free `MacHostMemory.QueryRaw` via immutable snapshot, ordered-set run ends and binary search; conflict med-high because of our `ExclusiveOwner`/ledger logic, so profile lock waits first. The timed-wait condvar rounding part is moot (we wait through `GuestWait`).

**3. Metal LOD statistics (M).** Upstream #1029 plus #1082's `VulkanVideoPresenter.LodStatistics.cs` make the guest's mip-statistics buffer reflect what the GPU actually sampled, so streamed textures only request the detail needed. Metal has no `TryRecordLodStatistics`; the default returns false and the interpreter writes "mip 0 sampled" for everything (`GpuCommandInterpreter.Memory.cs:546`, `MipStatistics.Shared.WriteReport`). Port: per-slot atomic min-LOD and count in the MSL pixel path driven by the existing `MipStatisticsDword` binding in the shared IR (`ResourceSpecialization`, `BindingLayout`, `ShaderCompileRequest`), plus `TryRecordLodStatistics` on the Metal host that publishes into guest memory. Validate with one DS run comparing resident texture memory and streaming reads; the evidence is indirect.

**4. #1074, shader seed (L, staged).** API-independent files (no Vulkan references): `AgcShaderHeader.cs` (header signature `31 32 33 34 18 00 00 00`), `GameShaderScanner.cs`, `ShaderInventory.cs`, `ShaderWorkList.cs`, `StaticStageInputs.cs`, `RecordDifference.cs`, `ShaderCodeCapture.cs`, `ShaderSeed.cs` (drop one `using Silk.NET.Vulkan`). Skip everything under `VulkanVideoPresenter.*` and the Vulkan binary/driver-stamp parts (our Metal compiler already runs out of process; `MetalShaderPrewarm.cs` measured 6 in-flight compiles as best). Stage 1: scanner as a diagnostic tool. Stage 2: `StaticStageInputs.TryCompute` into our `ComputePrewarmRecord`, plus `RecordDifference` to measure the derived-equals-recorded hit rate on already-recorded computes; that number decides whether to continue. Stage 3: wire static computes into `PendingComputes` behind the first-frame list; port the `PortableBufferWord` (buffer stride / descriptor word 3 as runtime shader data) compiler change only if mismatches demand it (touches shared tracker, `Gen5MslTranslator.cs:2156-2176`, `MetalRenderHost.Descriptors.cs`). Independent and cheap: the iterative `ResourceTracker.HasRuntimeRead` rewrite. Separate, our own idea inspired by it: prewarm Metal render pipeline states (`MetalRenderHost.Pipelines.cs:607-615`; 4.5 s of GPU-worker pipeline creation per warm run, one 535 ms stall) and evaluate `MTLBinaryArchive`. Watch the 3 GiB OS Metal cache cap: a very large seed can evict itself (`MetalShaderPrewarm.cs:488-495`). Upstream says the full precompile can take about an hour on DS.

**5. Chunked HLE string functions (S).** `TryCompareStrings` (`KernelMemoryCompatExports.cs:6148`), `TryCompareStringsCaseInsensitive` (`:8927`), `Strncpy` (`:842`) and `Memchr` (`:8716`) read one guest byte at a time. #636/#633/#632 apply cleanly: page-bounded chunk reads with vectorised compare/IndexOf, byte fallback only when a chunk faults. Take only the `strcasecmp` hunk of #637 (its strchr part is already in as `TryScanCString`). Also make `Strlen` (`:493`) span-based (it calls `TryReadCString(...).ToArray()` per call) and consider routing `strlen/strcmp/strcasecmp/strstr` to the loaded `libc.prx` through `IsSafeLleLibcExport` like memcmp (needs a correctness check). #631 (memcmp) is unused for DS because memcmp is already native.

**6. #1055, memcpy threshold (S).** Add `cmp rdx, imm32; jae slow` to the memcpy stub so copies of >= 4 KiB take the managed path (marks the destination written first, no per-page tracking fault); `SHARPEMU_MEMCPY_MANAGED_MIN` override. Our stub is `EmitGuestMemoryCopyStub` in `DirectExecutionBackend.FastPath.cs` (~line 380-388, next to the overlap `jb slow`). Measure write-fault counts on a DS run before and after; under Rosetta a fault costs about 0.2 ms.

**7. #958, view region table (S).** `src/SharpEmu.HLE/Host/HostViewRegions.cs:29-67` rebuilds and sorts the whole list on every `Replace`; `TryQuery`/`ChangeProtection` are linear scans, and `MacHostViews.cs` calls it on every view mmap/munmap/protect. Port the binary-search splice with neighbour-only merge and its differential test, keeping the table's `Gate`. Upstream diff retrieved during the survey: it touched `Host/Posix/PosixViewRegions.cs`. Combine with #1061's `ViewRecordTree`/`AvlSpanSet` only if view counts reach the thousands.

**8. #1061 `88f17d61c`, fiber race (M).** `FiberExports.cs` publishes `FiberStateIdle` on the outgoing fiber at lines 292, 505 and 643 while the import gateway on the native thread still reads that fiber's pack and stack; a second worker can resume it on a live stack. The commit defers idle publication until the gateway has switched to the host stack (passing a transfer stub into `ImportDispatchGatewayManaged`, `PendingFiberTransfer` in `FiberExports`) and rolls back on failure. Touches `DirectExecutionBackend.Imports.cs`, the x64 stub emitter in `DirectExecutionBackend.cs` (same bytes under Rosetta; revisit for ARM64), `GuestThreadExecution.cs`, `FiberExports.cs`. Race not verified empirically, and our Imports.cs diverges; reproduce or reason from a trace before porting.

**9. Jump-table resolver (M).** #926's `fix(loader): prove jump table bounds...` replaces `TryCollectJumpTableTargets` with a CFG-based resolver (selector bound proof, table-address proof, iterate to fixed point); on Tsushima it cut indirect-branch refusals from 55 to 8. Target: `GuestRedZonePatcher.cs:438-600` (we already have `TryCollectJumpTableTargets` at 438 and `TryResolveJumpTable` at 484 plus a decode-list reuse change). Success metric is the existing patch-log line (1395 -> far fewer) with no game run.

**10. #1079 AGC nop (S).** `sceAgcCbNop` must emit a one-dword type-2 filler and `sceAgcCbNopGetSize` must honour its argument; ours rejects `dwordCount < 2`. Take only these two hunks; the rest of #1079 is Saros-specific (MSL ops `ImageGather4L`, `VMadI16`, `DsOrderedCount` etc. are not needed by DS).

**11. #1039 (S-M).** Two parts in shared code used by Metal V2 through `IShaderPipelineHost`: a `ConditionalWeakTable` caching the sorted interpolated-attribute set per decoded program (ours scans with LINQ per draw at `ShaderPipelineCache.cs:373`), and a bypass of `ResourceMaterializationCache` for plans with under 1/8 hit rate after 64 lookups, re-probing every 64th draw (adds `CacheLookups`/`CacheHits` to `ShaderResourcePlan`, a `Bypassed` counter). `ResourceMaterializationCache.cs` has drifted, so merge by hand; check DS's cache hit rate in the existing `[PERF][RESOURCE_CACHE]` report first.

**12. MacHostMemory scans (S).** The O(1) uniform-region answer of #638 is already in (`MacHostMemory.cs:438`). Replace the remaining linear scans, `OverlapsTrackedRegionLocked` (`:518`, runs on every allocation) and the untracked next-base loop in `Query` (`:496-506`), with binary searches; `Regions` is a `SortedList`, so indexing is O(1). Coordinate with the lock-free query work in rank 2(d).

**13. Selector bounds (M).** `IndirectSelectorBound.cs` (new, self-contained) derives a proven upper bound from `min/min3/med3`, and-masks, `bfe`, shifts and selects, turning a plan failure at `ResourceMaterializer.cs:668` into a bounded probe; `b04e3cff8` preserves wrapped selector domain completeness. First look at DS plan-failure logs; all 184 dumped DS shaders compile today, so this may be pure hardening.

**14. HTile (M-L).** `edf20df57` records rewritten/expanded metadata clears faithfully; `e8d32903d` decides an in-place HTile rewrite's clear from the words it wrote. Port `RecordHtileRewrite` and the `IsHtile/ExpandMetadata/MarkHtileRewritten` additions to `IRenderHost` plus `MetalRenderHost.Images.cs:389`, and `ResolveRewrittenHtile`, `HtileWordsCleared`, `RewrittenByGpu` in `MetalImageCache.Tracking.cs` near `ClearMetadata` (line 977). The hard part is reading the HTile words back after a GPU compute write (needs a flush through `MetalGpuWriteRanges` / the staged-range cache). **15. Flat/smooth slot sharing (S-M).** In `Gen5MslTranslator.Interpolation.cs:105-137` a group mixing flat and smooth PS slots with no per-vertex owner becomes two inputs and `Gen5PixelInputMapping.ResolveLocations` moves the second to a location the VS never writes, so it reads zero.
