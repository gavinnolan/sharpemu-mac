# Bounded singleton 2D-array storage

The frozen8c19 first failures in Silent Hill, Octopath and Oregon share type13, 1x1, one array layer, format10/0, tile27 and base/selected mip0. They occur at 64KiB-aligned addresses. The retained diagnostics lack raw words; the new rejection includes them so a subsequent title run can distinguish unsupported metadata from the shape addressed here.

Admission requires eight copied raw words that decode identically to the frontend descriptor, one resource/view mip, layer0, baseArray0, arrayPitch0, zero metadata/flags/BCswizzle/minLOD/reserved fields and the actual compiled Float storage 2D-array shape with explicit Read/Write intent. Destination selection remains copied and is interpreted by the existing translated store/sampled view machinery; no numeric remap is introduced. Other arrays, dimensions, formats, mip selections and atomic/depth/MSAA shapes remain unsupported by this bounded path.

Mode27 is a 64KiB swizzle block in the existing `GnmTiling` physical-layout contract. The resource origin in layer0 and mip0 has zero spatial equation terms. The block-aligned address excludes embedded within-block address/XOR bits; this is a bounded origin admission, not a proof of arbitrary array slice XOR or stride. Snapshot creation reads the complete physical block and requires successful real detiling, then owns the four linear native RGBA8Unorm bytes. Failure cannot reinterpret raw tiled data as linear. The DTO retains the observed physical footprint for tracking/provenance; queued managed payload accounting counts the actual owned linear array and metadata, with native resource budgets separate. No late guest memory access is added.

The native texture is [MTLTextureType2DArray](https://developer.apple.com/documentation/metal/mtltexturetype?language=objc), with arrayLength1 and depth1, using the slice upload API for slice0. The live registry validates native dimension and array length, so a same-address plain2D texture cannot satisfy this binding. ShaderRead|ShaderWrite usage is retained without RenderTarget usage. Initialization and raced-publication errors release the newly allocated texture under the existing ownership convention. Presentation/blit/display paths retain their 2D guards. Sampled alias selection also compares array length and cannot use the existing plain2D depth snapshot route for an array declaration. General array feedback-copy/producer-version consumption remains separately unsupported; this change does not relax the existing 2D feedback guard.

Managed fixtures exercise actual descriptor→snapshot→format/layout paths, whole physical read, asymmetric and zero texels, detached raw/pixel ownership, negative metadata/shape/base/extent fields before any read, short/unstable seed rejection before native allocation, and same-address typed-view mismatch. A partial multi-image preparation failure releases its earlier captured source inside the existing rollback boundary. The private graph remains defaultfalse.

Native fixtures are source/build-only until separately authorized. They use the actual snapshot and storage materializer, then a guest-translated MIMG store/read at explicit x/y/layer coordinates. All four seed/result bytes and normalized Float loads are compared, with negative layer1, negative layer and x1 stores leaving slice0 unchanged. Physical guest padding is never written. Each fixture releases its created storage image and translated shader libraries in finally. This is not full game correctness, all-array capability or graph activation. Native required-device runs and exact-title reruns must precede runtime acceptance.

## Actual PERF_MOD 7 / BGRA descriptors

The later signed AE runs supplied exact descriptors for Silent Hill and Octopath: WORD3 `D1B00F2E`, WORD5 `00700000`, and otherwise the same bounded origin shape. The source qualifier now admits only WORD5 zero or `00700000`. [Mesa GFX10 resource fields](https://chromium.googlesource.com/chromiumos/third_party/mesa/+/refs/heads/stabilize-13982.70.B-chromeos-amd/src/amd/registers/gfx10-rsrc.json) place PERF_MOD in bits20–22; adjacent array pitch, maximum mip, warning, corner-sample, LOD counter, PRT and big-page fields remain rejected. Values1–6 also remain outside this narrow qualification. This changes performance-hint admission without altering physical placement, mip/layer selection or payload ownership. The managed producer replays both exact addresses and verifies detached descriptor/pixel copies; fourteen WORD5 near misses reject before any guest read.

The successor native fixture deliberately uses four different seed bytes `[17,83,149,227]` and logical Float store values `[1,0.5,0,0.25]`. F2E names B,G,R,A: the physical write oracle is `[0,128,255,64]`, while the logical sampled read oracle is `[255,128,0,64]/255`. A native 2D-array BGRA sampled view is used only for the ImageLoad-only binding, with the writable underlying texture remaining identity. Bounds-negative writes preserve all four seed bytes. No expected value calls the shared shader translator's swizzle helper.

The write oracle is an inference from independent AMD runtime source, not an AMD-device execution claim or an explicit RDNA2 IMAGE_STORE pseudocode quotation. AMD [ROCr's channel table](https://github.com/ROCm/ROCR-Runtime/blob/d614ea8bbd73a7832c265725117274d13041ff06/src/image/image_lut_kv.cpp) marks BGRA UNORM8 read/write and maps Z,Y,X,W. Its [GFX10 image manager](https://github.com/ROCm/ROCR-Runtime/blob/d614ea8bbd73a7832c265725117274d13041ff06/src/image/image_manager_nv.cpp) programs those selectors into the SRD and forwards ordinary fill patterns unchanged; the [fill kernel](https://github.com/ROCm/ROCR-Runtime/blob/d614ea8bbd73a7832c265725117274d13041ff06/src/image/blit_src/imageblit_kernels.cl) passes the unchanged Float vector to write_imagef. This corroborates inverse physical channel placement independently of SharpEmu. The [AMD RDNA2 ISA](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf), Table45, defines the read selectors but does not explicitly state the inverse store rule. The fixture qualifies the existing Metal translation against that stated oracle; game correctness and broader DMASK/selector semantics remain separate.

The previous PERF_MOD0/FAC fixture passed four required-device cases on each CLR at source1327230, but its symmetric magenta value did not distinguish R from B. Those retained runs do not qualify this successor's PERF_MOD7/F2E behavior. Native execution of the successor remains pending a separately reviewed frozen source and serialized grant.
