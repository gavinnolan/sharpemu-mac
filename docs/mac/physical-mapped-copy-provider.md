# Mac mapping-bound owned copies: source checkpoint

This isolated slice implements the previously unused optional mapped-copy contract. The initial source checkpoint was unbuilt; subsequent bounded qualification is recorded below. No Metal consumer, selected-image policy, fault handler, retry disposition, graph activation, content authority or native guest safe point is added.

`MacHostViews` records only successful shared mappings that cover complete measured kernel pages, with exact canonical backing identity, original backing offset, recorded readable access and monotonically assigned incarnation. Ordinary startup calls `_host_page_size` with the installed SDK's LP64 `vm_size_t*` ABI and releases its temporary host port. The optional capability remains unavailable if geometry or port cleanup fails. Kernel geometry is distinct from the existing POSIX/provider page property; existing provider fields and legacy mapping behavior stay unchanged. Full aligned records are admitted; Rosetta logical 4 KiB mappings that do not cover the measured kernel footprint remain unavailable.

The private ledger uses the existing `HostViewRegions.Gate`. Mac views hold that gate across each actual mapping effect and publication. Anonymous raw memory takes its existing `Darwin.Gate` then the view gate; view routes never acquire Darwin's gate. No new mapping drain or copy callback runs under either gate. Backing release first revokes associated observations under the view gate, then releases it and performs the exact alias unmap after existing backing accesses drain. Internal canonical aliases remain excluded during that gap and after uncertain cleanup. Every new anonymous placement, including shared-alias creation and relocatable hints, declines while any alias release is in flight; this prevents reuse before its exact native outcome is recorded. Unknown alias release permanently vetoes all previous observations and new anonymous placements. An unknown setup alias outcome retains a process-sticky conservative exclusion instead of inventing a removable range receipt.

Every participating map/restore/unmap/free/protect/commit effect revokes overlapping original states before the syscall, even if it later fails. Dormant private owned-operation effects participate per native page. Partial changes conservatively remove the whole old view from observation eligibility; this slice does not invent splitting or restoration of a retired identity. An unchanged tuple after remap gets a new incarnation. Exhaustion never wraps or recycles. A failed effect cannot make an old observation current again.

A copy resolves at most 64 immutable records under the provider gate, retains the exact backing's ordinary access pin, releases the gate, and copies from the backing's canonical alias rather than a guest virtual pointer. Virtual remap/unmap cannot invalidate that alias during the copy. The result is `Rejected` if original states were revoked or the backing closed; callers must discard the possibly modified destination. `Copied` transfers detached destination bytes and opaque owner-bound metadata, without retaining an access pin. `IsCurrent` visits only the captured states and scalar closure flags; it does not query kernel permissions or reconstruct mapping equality. It is a point-in-time mapping/lifetime veto using embedded opaque capture state (no lookup table synchronization), never an authorization for a later GPU write, native no-copy buffer, content freshness or atomic content snapshot.

`SharedBackingViews`, `GuestSpaceOwner`, `PhysicalVirtualMemory` and `TrackedCpuMemory` forward explicitly. Copies retain the backing alias independently of outer virtual-map gates; they do not repair protections, lazily commit, or use another backend on failure. Unknown wrappers, private/unbacked memory, unsupported geometry and holes decline. The provider-private ledger owner cannot be replaced by public segment metadata or a separately constructed ledger. Internal alias overwrite/protect/free/query through participating raw/guest routes is excluded; the exact provider backing-release callback alone owns legitimate alias cleanup.

Remaining routes are **uncertified**: direct tracker libc `mprotect`, PageGuard/native permission callbacks, raw exported alias pointers/descriptors, guest native/JIT stores, external OS syscalls, wrapper operations that bypass explicit forwarding and Vulkan/native GPU writes. Mapping metadata does not establish base guest permission obligations or their watcher cohorts. Managed notify-before-write tokens and fault dirtiness remain observational vetoes, not completed-store or copy serialization proof. No existing strict global epoch policy is removed. This slice does not fix Superliminal content-currentness or Poppy concurrent recovery by itself.

Prepared controls (not executed): pinned-array ledger copying, detached destination and physical offsets; same-value ABA; failed pre-effect mutation; unrelated mutation; canonical alias exclusion; exact backing/foreign ledger rejection; cross-segment coverage; holes/source bounds; kernel alignment/read access; deterministic copy/remap and copy/close pauses outside gates; exception-balanced pin release; in-flight placement exclusion; unknown alias cleanup global veto; 64/65-segment boundary. Actual fresh-process Mac controls must separately exercise real shared aliases, full aligned views, consumer copy, remap ABA, raw alias exclusion, raced copy and exact owned cleanup before any native qualification claim.

The next separately reviewable ordinary-writer slice will record physical backing-offset begin/end intervals for participating managed alias operations. It must distinguish active writes, completed writes and aborted partial writes; every begun intersecting write revokes content observations independently of dirty coalescing. It will not certify native guest stores or expose content authority to Metal. Aliases/raw/native/wrapper participation gaps must remain visible instead of treating an empty managed interval set as proof of fresh content.
