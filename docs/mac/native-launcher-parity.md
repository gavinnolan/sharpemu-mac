# Native launcher parity and qualification

The initial native launcher is now integrated locally. Feature parity remains incomplete. The source boundary is `SharpEmu.Application` for persisted settings, catalogue and launch plans, `SharpEmu.Launcher.MacOS` for AppKit and its owned process group, and CLI for platform composition. Native SDK handles stay private. No GUI, guest library, Skia or Avalonia dependency is introduced to fill a missing native feature.

## Exact visible proof retained from b1b9ff8

The isolated ad-hoc signed bundle at `b1b9ff8487efe030a3db122f1fda7ead38f24c2a` ran for 240.28 seconds under a 300-second watchdog, with an absolute ephemeral `SHARPEMU_DATA_ROOT`, updates/Discord disabled and two synthetic catalogue entries. No game ran. It exited zero, all retained child PIDs and the private groups were absent, and source/app hashes were unchanged. Evidence is in `artifacts/validation/integrated-20261007/package-agent/native-launcher-b1b9ff8-window`.

Actual interactions covered catalogue rendering, selection preservation after modeless settings Save/scan, sustained output with visible backlog-drop counts, an automatically cleaned natural-root-exit descendant retaining pipes (root status 7), and Cmd-Q from settings with the owned Stop-and-Quit confirmation. The cooperative child printed its TERM final message. A later group TERM returned EPERM and visibly canceled pending Quit; the session subsequently completed, and a second Cmd-Q closed the app. The diagnostic remains a failure receipt, not proof that that signal succeeded. The displayed `-2` is the owner's explicit stop-request tag; the synthetic TERM handler exited zero. The error required scrolling to the console tail because autoscroll is absent. Minimum resize was attempted without an observed frame change and is unqualified. Cmd-W and Escape did not close the console/settings. The native typed controls added after this frozen revision are not covered by these screenshots.

## Implementation order

1. Qualify typed modeless settings and persistence retry without changing the schema. Finish display-choice and localization seams after the static choice controls are proven.
2. Establish adaptive window/layout ownership and standard window commands, then implement native Grid/Carousel presentation and recent menu. Preserve selection by executable path through filter/rescan/layout changes.
3. Add composition-only neutral launcher input, then qualify physical controller navigation. Add console filter/autoscroll/placement on the same native layout foundation.
4. Add the independent Mac Discord transport and native title preview. Keep optional services from owning the main loop or blocking Quit.

Each step needs its own source review and bounded qualification. A passing parser/process test is not proof of native controls, rendering/layout, controller hardware, Discord transport, game compatibility or complete frontend parity.

The typed-settings package build passed with zero warnings/errors. The complete native launcher managed/synthetic-child suite passed 36/36 on ARM64 and 36/36 on x64/Rosetta with zero declared skips. Added cases exercise actual schema coverage and unchanged serialization, inherited boolean state mapping, unknown choice retention, and an actual editor Save callback failing persistence then accepting later edited values on retry. No AppKit window/control was created by this test selection. The existing Mac-only process fixture early-return gates remain in source; both qualification CLRs executed on macOS. No shared Application/Core/guest source changed, so these tests do not claim new Windows/Linux runtime behavior.

The native choice control follows Apple's [pop-up button target/action and menu API](https://developer.apple.com/documentation/appkit/nspopupbutton); its text guidance uses the native [text-field placeholder API](https://developer.apple.com/documentation/appkit/nstextfield/placeholderstring). Controls and callbacks retain the existing editor ownership: disconnect before closing, release after reverse callback return, and retain all pending handles if the main loop ends first.


The explicit-persistence successor adds `SaveOrThrow` to global settings, per-game overrides and global custom environment stores. Legacy `Save` remains best-effort. Native explicit editors propagate persistence failures, keep the editor open and distinguish them from invalid field input. Global editing clones the full model and its lists; only successful persistence publishes the normalized draft as live application settings. Folder/exclusion/close convenience writes still use the legacy best-effort API.

Writes stage a complete UTF-8 file in the destination directory, flush it, then replace the live file; failed staging/replacement never truncates the old file. New Unix files start owner-only, and existing Unix modes are copied onto the staged file. Ordinary temporary cleanup errors are retained as secondary context without replacing the primary I/O error. This does not claim directory-fsync crash durability, concurrent-editor conflict prevention, extended Unix ACL preservation or followed-symlink identity. Existing-path replacement changes the path entry; deployments using a symlink to the settings file need separate review.

The isolated workers exercise all three real stores with blocked paths, valid prior JSON, denied directory writes, byte-identical prior-file checks and successful retries. On macOS an internal, default-null safe-context seam revokes the owned directory's write permission after staging; real replacement and temporary-unlink failures prove that the original failure and secondary cleanup context both survive. No production configuration enables this seam. Windows source has an existing-file share-denial control, but Windows runtime behavior is unexecuted on this machine. No AppKit window or actual disk-failure alert has yet been qualified for the successor.

Static suggestions now only offer admitted choices (ConsoleType PS5; LogLevel also None). A production-normalization regression enumerates every supplied global menu option to catch silent coercion. Unknown raw inputs remain in the editor until the existing normalization runs; this is not a guarantee that arbitrary future global modes persist unchanged.

The explicit-persistence successor passed Application 76/76 and launcher 38/38 on both native ARM64 and x64/Rosetta, with zero declared skips. Both package test builds and the neutral Application win-x64/linux-x64 cross-builds reported zero warnings/errors. The native launcher suite's existing Mac-only process fixtures executed on this machine; their off-platform early returns remain explicit. Application workers invoke the real isolated stores; the live-model acceptance callback is independently exercised with a propagated synthetic I/O error. Actual AppKit typed interaction, actual failed-save alert/retry and Windows/Linux runtime filesystem behavior remain unqualified. The initial environment worker failure was a fixture mistake (punctuation is admitted in names); the failed 75/76 run is preserved before correcting the negative to an empty name.
