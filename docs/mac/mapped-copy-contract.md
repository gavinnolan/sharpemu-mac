# Optional mapping-bound owned-copy checkpoint

The original source-only checkpoint added an unused neutral capability and immutable exact mapping footprint. The isolated Mac provider implementation is described in [physical-mapped-copy-provider.md](physical-mapped-copy-provider.md); no presenter consumes it. No global epoch, content observation, selected-mip key, graph enablement or Poppy fault acceptance changes. Build/test/native execution are pending a separate release/grant.

`ICpuMappedCopySource` is an optional ordinary-thread operation, separate from `ICpuMemory.TryRead`. The requested source bytes lie inside a separately declared mapping footprint. For DS these are131072 bytes at resource+131072 versus the retained262144-byte resource-prefix footprint. `Copied` requires complete caller-owned destination bytes and an opaque observation; `Unavailable`/`Rejected` cannot authorize publication and may leave partial destination bytes to discard. Consumers retain the existing strict policy when this capability is unavailable; they must not retry through another backend or silently remove the global veto.

Only the neutral owner can construct `CpuMappedCopyObservation`. It owns a detached read-only segment array and private owner-reference identity, with a hard limit of64 segments (checked before cloning or walking), overflow-safe exact coverage and read-entitlement checks. Segment metadata preserves mapping incarnation, canonical backing identity/logical size/offset, complete mapping extent versus covered extent, process-provider page size and captured guest access. It is not proof that those caller-described values are true native operations. No pointer/handle/content token/native receipt is returned; no access pin remains held by the observation. Owner `IsCurrent` must reject foreign observations and use its authoritative immutable mutation-participation state with at most64 captured segment visits. Equal values reconstructed from the current mapping API or HostMemory.Query do not prove incarnation identity; same-value remap ABA must still reject. Metadata-only construction cannot qualify a provider.

The future owner allocates positive monotonic signed64-bit incarnations under its ordinary mutation coordination. It must never wrap, recycle, reset on Clear or reuse an incarnation after a failed operation. After assigning long.MaxValue, further observation-producing mutations must decline/quarantine for the rest of that process; an owner replacement must not recycle the counter; the isolated provider now assigns these identities, with qualification pending. Constructor rejection of nonpositive values is only metadata validation, not this allocator proof.

Incarnation must change on actual map replacement, including identical address/backing/offset ABA. A split preserves unchanged identity only if its original native mapping was untouched. Partial/unknown native outcome closes/quarantines affected identity. Backing identity must be the canonical shared object across aliases; provider-reported POSIX4K/Rosetta or16K/ARM process page size is not a universal physical Mach-page proof. A future native provider record must additionally retain its exact successful allocation/mmap extent; this DTO deliberately does not fabricate that kernel receipt.

Before an implementation is eligible:

1. PVM must hold its region/base-ledger coordination and use GuestSpaceOwner mapping coordination while resolving exact segments/offsets and completing an alias-backed copy under balanced ordinary storage access. No lazy commit, temporary protect or tracker callback under those gates. Existing fast TryRead remains unchanged.
2. GuestSpaceOwner/SharedBackingViews must assign immutable per-mapping incarnation and deny/newly close observations during map/unmap/split/restore/dispose. Existing alias access protects backing disposal only; it cannot be renamed as virtual mapping or writer authority.
3. MacHostViews and canonical MacHostMemory raw/neutral mutation routes must participate before syscalls across every affected native extent (MAP_FIXED, free, protect/commit, interior/cross/overrun/rounded ranges, alias and backing retirement). Raw overlapping calls reject or use the exact provider-owned pending operation. Any required close/drain occurs outside PVM/mapping/stripe/view/provider gates, followed by exact pending-operation revalidation. No public cookie or TLS bypass.
4. Tracker direct libc mprotect remains unhooked; complete permission/recovery authority is unavailable until a separate signal-safe protocol is proved. Managed notify-before-write, native delayed stores, and physical alias writer fanout do not become serialized by mapping metadata. Existing generation/content/trap checks remain required, and atomic stable-content certification remains unavailable.
5. Wrapper capability forwarding must be explicit and preserve LastFailure semantics. Unsupported/private/lazy memory is unavailable. A presenter validator cannot acquire provider/registry locks or call HostMemory.Query under its GPU gate. No selected GPU owner may reuse a remapped address without mapping incarnation, but no presenter path changes in this checkpoint.

Genuine controls to prepare after contract review: exact DS source-versus-prefix footprint; detached/immutable segment storage; holes/overlap/overflow/malformed geometry/read-entitlement rejection; copied ticket foreign-owner and same-value map ABA; unrelated mapping/protect mutation versus exact-target mutation; disposed/revoked/partial-failure owner; wrapper and unsupported capability; mapping-held copy against paused remap/dispose; native exact-range/generated-outcome controls only after a separate bounded grant. Real actual PVM/provider tests must exercise admitted operations, not just construct a DTO. Pure metadata tests can validate only shape/immutability. No callback, native fault, permission retry or graph source certification is implied.

Source-only shape controls are prepared in `CpuMappedCopyObservationTests`: exact DS split prefix/source extent,64/65-segment boundary, detached read-only storage, owner-reference identity, backing metadata consistency and malformed source/coverage/rights/geometry. No control has been compiled or executed at this checkpoint; no producer, currentness method, incarnation allocator, mapping interleaving or native operation is covered by those metadata fixtures.
