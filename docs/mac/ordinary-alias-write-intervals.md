# Ordinary canonical-alias write intervals: source checkpoint

This separate source-only successor adds internal, opt-in bookkeeping for participating managed destination writes. It is unbuilt and unexecuted. It exposes no new content-authority capability to Metal and does not alter mapping-only `IsMappedCopyObservationCurrent`, guest/native fault handling, graph activation, writer permissions or copy serialization.

The exact canonical `HostBackingObject` owns one interval ledger. Optional mapping-bound copy enrollment publishes a fully constructed ledger with one compare/exchange; concurrent first copies may allocate unused candidates. Enrollment has no waits or callbacks. Legacy unenrolled writes read a null reference and keep existing behavior. Warmed enrolled writes use only fixed preallocated slots, value tokens and scalar atomic operations, with no new allocations, clocks, queries, callbacks or waits under provider/PVM/view gates.

There are 128 slots. Every nonempty, in-bounds participating destination first receives a positive monotonically increasing operation identity. Reservation CAS changes an empty slot to `-identity`; offset/count are initialized, then `+identity` publishes the active interval before actual bytes. Completion consumes exactly `+identity` to empty in one CAS before slot reuse. The token binds ledger identity, slot and operation identity; a copied/stale/foreign token cannot release a later operation or repeat a completion. Completed and aborted counters are distinct. The fixed slot scan is bounded; saturation, identity/counter exhaustion or malformed offset/count makes bookkeeping coverage sticky incomplete while the legacy write continues. Empty writes do not become intervals.

`SharedBackingViews` brackets the actual `NativeMemory.Clear`, single-view `Span.CopyTo`, multi-view destination chunks, overlapping/memmove copies, nonoverlapping `Buffer.MemoryCopy` chunks and staged cross-segment writes. Existing alias access pins remain held until the bytes and finally completion finish. The original copy functions, chunk order and staging/overlap selection are preserved. A later chunk failure does not roll back earlier bytes or turn earlier completed chunks into an atomic transaction. A valid destination's ordinary exception consumes its interval as aborted in finally; the byte write is never retried by this bookkeeping.

PVM/GuestSpaceOwner managed alias `Clear`, `TryWrite`, `TryCopy`, `TryWriteBacking` and renderer download paths that actually call these alias helpers participate through their existing forwarding. Paths that use direct private guest pointers, exported raw aliases, external syscalls, native/JIT stores, Vulkan/native GPU aliases or unknown wrappers remain uncertified. Pre-enrollment writes can already be in flight when enrollment publishes. An empty interval set, a completed counter, or a mapping observation is therefore never proof of fresh or serialized guest content. No content observations are issued, no existing CPU/GPU owner is retimestamped, and no native write-through is enabled.

Private test observations of active slot metadata are fuzzy under concurrency: a reserved slot may not yet be published and completion may be between its slot CAS and counter update. They are ordinary diagnostics only, never an admission predicate. Quiescent counts and exact token consumption can be tested; they do not constitute a native store-completion receipt.

Prepared controls use pinned managed arrays and reflection on the internal bookkeeping only: legacy non-enrollment; real alias Clear/write/memmove and cross-segment staging byte equivalence; empty/rejected bounds; mapping currentness remains separate; exact physical offset and distinct scalar abort; copied/stale/foreign token rejection; saturation/exhaustion with preserved legacy writes; warmed actual single-view no-allocation. Scalar aborted intervals do not qualify a deliberately injected native/partial-write failure. Native guest stores and all-alias safe-window serialization remain future prerequisites.
