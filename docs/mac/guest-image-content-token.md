# Content observation across tracker retirement

`GuestImageWriteTracker.TryGetContentToken(address, out token)` is a safe-context observation of both protected and managed-watch registry owners. The immutable `ContentToken` includes their separate monotonic owner identities, write generations and byte extents. Missing components have identity zero, generation minus one and extent zero. The method returns false when neither owner exists.

Owner identity matters because removing a range and registering that address again can restart its generation at zero. A copied generation-zero seed could otherwise compare equal after a write advanced the old counter to one and tracker retirement removed that counter. Both protected and watch owners must be kept separate: their existing aggregated generation is useful to legacy caches but cannot express independent owner replacement.

A producer that needs tracked freshness must establish observation of the full source footprint, capture the token before reading bytes, require appropriate owner coverage, compare the exact token after the copy and retain that original token with the owned bytes. Before admission/consumption it compares the retained token again. Unknown observations and changed identities, generations or extents must be rejected in that path. Reading a new token after copying bytes and attaching it as their provenance would repeat the stale-seed bug. Expanding an owner replaces its identity; this API intentionally does not authorize reconciling old copied bytes with that replacement.

The tracker gate stabilizes registry identity and extent lookup. Individual counters may advance concurrently when a signal or managed writer marks content. The token reserves neither content nor a mapping, does not prove coverage of raw native stores by a managed-only observer, and is not a protection receipt or a retry claim. Native backing lifetime and write observation must be established separately. Legacy `ReadSnapshot`, generation and signal/fault APIs are unchanged.

The managed tests exercise real watch-only tracking, managed write notification, dirty consumption, selective retirement, recreation and extent expansion. A separate explicit protected-registry metadata fixture checks independent owner fields without arming pages or invoking native callbacks. There are no device-gated early returns in these tests. They prove observation/ABA rejection semantics, not native mapping ownership or game progress.
