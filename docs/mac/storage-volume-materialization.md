# Bounded native storage volumes

Storage image type 10 / shader Volume is native Metal texture3d, including depth 1. The registry preserves native type/depth alongside extent/format, rejects mismatched live views, and uses shader read/write usage without render-target usage. Two-dimensional flip, render target, feedback copy, blit, CPU synchronization, and per-frame presentation paths reject a volume before a 2D operation.

A new native image requires a stable, complete owned linear seed. Deferred XY-only detile payloads are rejected for storage volumes. Linear volume rows use pitch*bytesPerTexel and full padded image strides of pitch*height*bytesPerTexel, including the final row of every depth slice. Checked multiplication and a managed snapshot size limit precede allocation. Width, height and depth are bounded to 2048, matching Apple's documented maximum 3D dimensions in the [Metal feature tables](https://developer.apple.com/metal/Metal-Feature-Set-Tables.pdf). Upload uses the existing slice-aware region API; Apple's [replace region documentation](https://developer.apple.com/documentation/metal/mtltexture/replace%28region%3Amipmaplevel%3Aslice%3Awithbytes%3Abytesperrow%3Abytesperimage%3A%29?language=objc) defines bytesPerImage for 3D texture uploads.

Volume materialization requires the complete raw 8-word descriptor to decode consistently with the typed address, dimension, depth, tiling and format, with base/last/max mip 0. MetadataAddress, DescriptorFlags and BC swizzle must all be zero. The CPU snapshot checks those decoded properties before reading memory. Unknown metadata or compression flags remain unsupported; write access alone does not establish full coverage and never permits an invented zero seed.

## Singleton tiled origin proof

The singleton tiled qualification is deliberately limited to mode 27, one resource mip, aligned address (low 16 bits zero), width=height=depth=1, and the uncompressed descriptor bounds above. It copies only the origin texel bytes; it does not invoke the emulator's XY-only 2D detile equations for 3D data. Larger WxHx1, nonzero embedded XOR bits, additional mip offsets, unknown modes and depth >1 tiled volumes are rejected outside the exact mode 5 case below.

The conditional origin inference uses AMD's [GFX10 AddrLib](https://raw.githubusercontent.com/GPUOpen-Drivers/pal/dev/src/core/imported/addrlib/src/gfx10/gfx10addrlib.cpp): SwizzleModeTable entry 27 is 64KB_R_X; ComputeSurfaceInfoMacroTiled sets all single-mip offsets/tail coordinates to zero; ComputeSurfaceAddrFromCoordMacroTiled applies a block-masked pipe/bank XOR to the coordinate equation. At x=y=z=0, that equation contributes zero. AMD [PAL GetMipAddr](https://raw.githubusercontent.com/GPUOpen-Drivers/pal/dev/src/core/hw/gfxip/gfx9/gfx9Image.cpp) embeds pipeBankXor in the hardware image base at bit 8. The local Prospero T# decoder reconstructs the full base from raw words 0/1 with an eight-bit shift and does not erase the embedded low bits. Thus an aligned 64KiB decoded base forces the effective low-block XOR to zero under that hardware descriptor contract. This is an inference from the documented implementation, not a general 3D detile implementation. A decoder fixture explicitly varies embedded low address bits and verifies they survive decoding.

The observed dd19 Poppy failure had type 10, 1x1x1, fmt 10/4, tile 27 and address 0x90073C0000 with one resource mip. That prior failure did not expose raw words 6/7; its metadata safety is not yet established. The next frozen runtime must retain the exact raw descriptor. A descriptor rejected by these bounds is reported, not reinterpreted.

## Qualification scope

Focused managed fixtures cover native identity, padded strides, partial/unstable seeds, overflow, capability bounds, descriptor consistency and metadata rejection before any memory read. Native fixtures call the production storage materializer, read every texel of padded-pitch RGBA8Uint volumes of depth 1 and 3, execute actual guest-translated MIMG store/load at a selected 3D coordinate and compare untouched texels/slices with a sentinel oracle. The singleton fixture exercises production snapshot->materialization against nonzero tile padding. Native readback proves the upload and shader binding; the origin source proof above is separate. These fixtures do not certify complete production ComputeDispatch ordering, storage CPU readback, arbitrary tiled 3D layouts, Poppy progression or CPU fault recovery.

Validation on clean source `6fd5a27` completed: 97 managed Metal VideoOut checks passed; 39 production materialization checks passed with `SHARPEMU_TEST_REQUIRE_DEVICE=1`, zero runner skips/failures. The three new actual device cases verified native depth 1/3 padded seeds and translated 3D store/load plus metadata-zero mode27 singleton origin upload. The device selection also contains pure contract tests;39 is not a claim of 39 GPU dispatch fixtures. Local stdout, exact DLL hashes and cleanup assertions are under `artifacts/validation/volume-storage/` in the CPU volume worktree. The initial singleton fixture used the wrong positional binding argument; corrected named ResourceDescriptor passed. A build-only 180s stall was preserved separately, followed by a successful separate build and device run. No game ran; Poppy metadata and full dispatch behavior remain unqualified.

## Exact mode 5 R16Uint16 cube

The later Poppy binding has raw words `7AC109C0 C0B00000 0003C003 A0500004 0000000F 00700000 00000000 00000000`. The unified format extraction `(word1 >> 20) & 0x1FF` is **0x0B/R16Uint**, not 0xB0/BC4; the earlier artifact interpretation was corrected with preserved errata. Captured guest IR pc0xB4 is ImageStore; compiled metadata is Volume/Storage/Uint/Write and translated MSL writes `texture3d<uint>`. This proves a storage writer, not full texel coverage or permission to discard the initial bytes.

A second independently qualified layout is type 10, tile 5/ADDR_SW_4KB_S, R16Uint, 16x16x16, one resource mip, 4096-byte-aligned address and DstSelect 4/X000. All non-address raw fields must match the observed descriptor, including zero metadata/flags/BC swizzle. The typed descriptor must equal the raw decode before snapshot reuse or any memory read. Native materialization independently checks its view/raw fields and exact 16-texel seed pitch. All other tiled storage volume shapes remain unsupported. This mode 5 admission is storage-only. All sampled tiled type10 bindings (including modes5/9/27) are rejected before snapshot reuse, upload-known checks or any guest read, so they cannot enter the old XY detile/raw fallback path. Linear sampled volumes retain their existing route, which is not newly certified here.

The host-neutral `SharpEmu.Libs.Gpu.Images.Gfx10StandardVolumeLayout` performs trueXYZ reorder into a separately allocated owned destination. It cannot reorder in place. The physical extent is 8192 bytes, overriding the legacy XY-per-slice calculation. Existing tracked read/stability checks remain; this does not add a host mapping lifetime reservation.

The primary oracle uses public APIs in [AMD AddrLib pinned PAL commit c5e8000](https://raw.githubusercontent.com/GPUOpen-Drivers/pal/c5e800072a32f68b6ccc4422936d96167c6e0728/src/core/imported/addrlib/src/gfx10/gfx10addrlib.cpp), with GFX10.3/Navi21 revision 0x28, 16bpp, TEX_3D, mode 5, one mip, no metadata. It reports block 8x16x16, pitch 16, height 16, slices 16, 8192-byte allocation, 4096-byte base alignment and zero mip/macro/tail offsets. All 4096 XYZ offsets are unique, even and within 0..8190. Several Navi21/22/23 configurations and a Navi10 control produce identical bytes; pipeBankXor 0/1/3/15 has no effect in non-XOR mode 5. The desktop ASIC choices are oracle configurations, not an assertion about the guest's exact hardware revision.

The independent captured CSV (SHA256 `f2f46cb04772b76e8d15823a98be422c1e1ac3074965a4e0ce551afe00bed690`) and public-API generator/source license are retained in `tests/Fixtures/Tile5Volume`. Managed checks compare the production decoder against every captured coordinate and reject nearby dimension/format/alignment/mip/metadata/raw-field cases before reading guest bytes. Native qualification is recorded separately after its required-device run; no complete ComputeDispatch ordering, Poppy progression, CPU recovery or general 3D layout claim follows from this bounded change.

The first native run at `7fc2c8b` passed 39/40: all native seeded texels and the translated write matched, but the load-only fixture incorrectly bound the identity writable texture to a sampled binding, returning alpha 1 instead of the T#'s alpha 0. The corrected fixture binds a same-format native 3D X000 sampled view for the translated load and leaves the original identity image for stores. AMD's [RDNA2 ISA section 8.2](https://gpuopen.com/download/rdna2-shader-instruction-set-architecture.pdf) specifies descriptor-selected missing texture components; Apple's [texture view API](https://developer.apple.com/documentation/metal/mtltexture/newtextureviewwithpixelformat%3Atexturetype%3Alevels%3Aslices%3Aswizzle%3A) supplies the native sampled swizzle. This is a translated sampled-load qualifier through an explicit correct view, not a claim about complete production 3D sampled materialization or storage-load ordering. No production shader read semantics were changed.
