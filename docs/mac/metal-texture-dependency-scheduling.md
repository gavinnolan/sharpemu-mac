# Captured texture source queue selection

The Metal-local selector inspects each scheduled logical queue head at most once per selection. It does not expose later work from a blocked queue. A captured source whose producer is still queued in another logical queue blocks that head while allowing the producer's queue or unrelated ready heads to progress. Selection retains the existing round-robin cursor; admission sequence is an identity, not a global execution sort.

`Pending` means a real queued producer still needs encoding. `Encoded` means the immutable source copy is safely ordered before its consumer on the one serial Metal command queue. It does not mean hardware completion: submitted native use must retain its own resources until the completion/error lifecycle ends. A pending producer that is missing, is the consumer itself, or is behind that consumer in the same FIFO queue is an explicit failure. If a full bounded head scan finds only pending cross-queue dependencies, there is no runnable encoding head; the selector rejects that dependency cycle rather than indefinitely holding admission pressure.

Selection failure records the cause before reporting it, wakes blocked admissions, drops the borrowed uncommitted batch handle and invalidates source version metadata. Unexpected readiness lookup exceptions use this same path and retain their original cause as the fatal exception's inner exception, so the drain finalizer cannot commit an earlier batch. Intended fatal paths already latched are not reported again. Failed work is neither removed nor acknowledged complete, and subsequent admissions return zero. The batch belongs to its creating autorelease pool; no native release or partial commit occurs in the selector.

This branch's foundation is not an active native source graph. Before integration, Metal admission must supply captured input plus initialization/WAW owners; source completion must publish `Encoded` only after faithful immutable copy commands; and the centralized failure path must cancel queued/native-use ownership and dispose uncommitted native resources safely. A metadata-only invalidation hook does not satisfy those resource obligations.

`MetalTextureDependencySchedulingTests` uses actual production Submit/TryTake/Drain queues and private captured-source associations. Source status and impossible graphs are deliberately injected into those real owners. The drain progression fixture executes a managed producer and expires the normal render budget before native compute execution. These tests prove queue ordering, rejection, failed-work noncompletion, frame-boundary fatal behavior and real backpressure wakeup without requiring a device. They do not prove native copy correctness, GPU completion retention, producer ownership, CPU/mapping exclusion, or game progression. No device-gated early return exists in this suite.
