# Controlled vertex-prefix policy and producer payload counters

The integrated successor keeps the prefix safety checks and public payload descriptors unchanged. Cached `SHARPEMU_METAL_VERTEX_PREFIX=0` bypasses planning entirely and preserves the original vertex-then-index capture order. `1` or an unset variable selects the bounded prefix path. Neither setting claims a temporally atomic guest snapshot. Its signed3815 source has actual [Dreaming Sarah runtime evidence](validation/vertex-prefix-abba-20261008.md); that app predates the combined-main build.

Cached `SHARPEMU_PROFILE_PERFORMANCE=1` enables one fixed, process-lifetime producer aggregate. With profiling disabled, draw accounting reads no clock, allocation counter, thread identity, environment or counter storage, and takes no instrumentation lock. The constructor warms the enabled storage on an ordinary safe path. The enabled path takes two brief independent instrumentation locks per attempted vertex capture; no GPU gate, provider operation, formatting or callback runs inside them. There is no per-draw output.

Attempted scopes start after resource collection and cover prefix planning/its optional owned index capture and CopyVertexBuffers. Copied means that CopyVertexBuffers returned completely; it is not backend submission, GPU dispatch or work acknowledgement. Baseline trailing index capture occurs after this accounting scope. A subsequent index, target or backend failure does not undo already copied vertex bytes. Failed scopes include failures before vertex copy completion; their partial byte totals are omitted and coverage is incomplete. Active scopes at shutdown are explicit. Packet eligibility only describes the synchronous invocation; metadata qualification is counted only when planning executes and succeeds, before index-data bounds checks. With policy off it is reported as unknown, rather than an inferred zero.

Full requested bytes sum original input buffers once, not attributes. Actual copied bytes sum the detached stream arrays, including submitted snapshots, prefix copies and baseline transient clipping. Neither total measures managed allocations, native allocations, GPU execution or content freshness. Shared attributes do not double count a stream. Successful captures with unrepresentable byte totals are rejected samples, not zero-byte captures. Checked overflow is sticky and marks coverage incomplete without publishing a partial tuple or replacing guest failure.

EndReport takes one coherent aggregate snapshot, then formats and writes outside the gate. Counts may still advance after that boundary; active scopes disclose in-flight work, and no global producer quiescence is inferred. There is no reset/window API; multiple presenters in one process share this lifetime aggregate. The optional report is best effort, independently attempted in the existing profile End finally, and cannot replace the original guest/shutdown exception.

Source controls cover actual SubmitDraw stream accounting/read order in fresh policy/profile process combinations, vertex read failure, cached flags, failing report sink, disabled zero-allocation scopes, concurrent aggregate snapshots, overflow and explicit active/unknown-byte tails. Existing bounded-prefix native stage_in proof is separate from these producer counters. A repeated native run will assert actual process architecture through the shared required-device helper. No game performance or optimization benefit is established by source controls.
