# Indexed vertex prefix candidate

The bounded indexed vertex prefix was developed on isolated source based on `2adf328d231d3e2c67c8dfe951f61939a60395a1` and is now imported into local main. The final profiling successor passed genuine managed and required native checks on both actual CLR architectures; its signed3815 app completed a four-run Dreaming Sarah comparison. See [runtime evidence and limits](validation/vertex-prefix-abba-20261008.md). Exact combined-main qualification is recorded separately after integration; original failed checkpoints below remain historical evidence.

The observed Sarah EventPipe producer summary had 50,013 byte-array allocation tick samples in `CopyVertexBuffers`. These are sampled allocation stacks, not exact allocation counts, bytes or draw counts. The indexed draw path is the target. This candidate does not pool arrays, change return authority, narrow the submission prepass snapshot or move capture to the presenter.

## Admission and ownership

The Metal command-stream override scopes original packet provenance only across its synchronous inherited translation/executor invocation, restoring it in `finally`. It is instance-scoped under the existing one-interpreter-host-thread synchronous invocation contract, not a cross-thread authorization token. Only direct bounded 16/32-bit indexed packets with original base vertex and first instance zero, a normal original topology and no restart qualify. Indirect, resolved indirect, 8-bit expansion, retained replay and non-indexed draw invocations fall back. The actual host-emitted first index, first instance and base vertex must also be zero; normalized pipeline topology/restart is checked independently.

Candidate inputs are capped at five vertex streams (the existing native slots26..30) and31 attributes before any candidate arrays or quadratic slot-group walk. Larger inputs retain the old path and its original errors; shared-stream deduplication is not used to broaden this cap.

All full original vertex and index extents must fit the obtained bound buffers and owned transient arrays before any early index capture. Zero stride/record count, unknown native vertex format, attribute thread-index/swizzle behavior, inter-record attribute overlap, unused streams, overflow and incomplete metadata fall back. This candidate excludes zero stride instead of guessing its existing special semantics. It does not change GPU descriptor bounds or reinterpret the record count.

One complete owned index byte array is captured and scanned, then reused unchanged in the queued draw. Per vertex stream, the prefix begins at the original origin and ends at `maxIndex * stride + max(attributeOffset + exactNativeFormatWidth)`. Per-instance streams instead use `(instanceCount - 1) * stride`; first instance/divisors are not inferred. Every referenced record must fit its declared record count. Native float4 remains sixteen bytes even when compilation uses two components. Attribute views of one input stream share the same union prefix and detached byte array. Original native slot-sharing groups (address/stride/full length) retain a common union prefix; an ambiguous instance-step group or a newly equal shortened length across distinct old groups falls back. This preserves the existing native descriptor/bind partition, whose lookup includes length. Descriptor record counts remain unchanged; the new length covers the actual emitted indexed native fetch footprint, rather than claiming the whole declared buffer was uploaded.

`SubmittedVertexData.CopyBufferPrefix` copies from the original private full capture into a new owned draw array. It never returns the private capture array. Replays and later guest mutation cannot change that submission capture. Ordinary non-submitted prefix reads also allocate detached bytes exactly as the original full copy did.

## Capture order and fallback

Resource collection stays first. Metadata-ineligible draws retain vertex-copy then index-copy order. Metadata-eligible draws capture indices before vertices, because the captured indices determine the safe prefix. Data-dependent OOB indices fall back to full vertex copies but reuse that earlier owned index capture. An eligible index read failure can therefore surface before a vertex read that the original path would have attempted first. This changed capture order is deliberate; no second index read can race the scan and queued draw. This does not certify simultaneous atomic capture of guest indices and vertices, backing lifetime or write serialization beyond the existing owned-copy boundary.

## Qualification requirements and historical checkpoints

- Actual executor/SubmitDraw controls: Uint16/Uint32 sparse maxima, full native fetch width, interleaved attribute union and per-instance bounds; independently exercised original packet classification.
- Full-copy fallbacks: OOB/restart/indirect/legacy topology, offsets, zero stride, unknown formats, invalid obtained/transient extent and incomplete indices; preserve existing invalid-read outcomes where metadata fallback applies.
- Actual submitted full snapshot followed by guest mutation: prefix data retains original bytes, draw mutations cannot affect a replay or the full private capture. Test original bound offsets and merged ranges.
- Native stage-in indexed readback using production-created vertex descriptor and actual prefixed arrays: Uint16/Uint32, asymmetric float4 lanes with compiler-used component count two, interleaved offsets and a separately stepped instance stream. Require native pipeline creation and actual command completion; compare full and prefix inputs against an independent complete output oracle. This is distinct from ISA translation, game execution or Drain proof.
- Exact-head measured producer allocated bytes and serialized Sarah comparison are separate later requirements. No optimization, FPS or startup improvement is claimed from source or CPU controls.

The source-only native fixture `IndexedVertexPrefixNativeStageInMatchesFullInputsAndAllSparseInstanceResults` is now prepared: four intended cases (Uint16/32 × owned-current/submitted). Each compares a full256/32-byte input with a prefix184/24-byte input using the actual production vertex descriptor, two shared interleaved attributes and an independent instance stream. It requires native pipeline creation and completed command status, then checks all128 output floats including uninvoked sentinels. Each case also calls the real prefix partition predicate on distinct original256/512-byte streams whose new184/184-byte lengths would collide; it must decline. A third actual native draw uses that original distinct partition and an asymmetric second-attribute oracle, verifying why full-copy fallback is required. This structural predicate control is separate from the actual executor fallback controls; it does not pretend to be a complete packet-to-native invocation. A handwritten MSL vertex oracle/direct native indexed call isolates stage-in fetch semantics; it does not exercise production EncodeDrawCall/Drain or Gen5 ISA translation. The submitted cases poison guest seeds before any native use and prohibit late reads. Compilation and all execution remain pending.
