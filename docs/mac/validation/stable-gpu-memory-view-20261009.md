Direct execution creates a distinct `TrackedCpuMemory` for each guest thread. AGC submissions attach each submitting thread's memory to the presenter, while the Metal command stream retains its first host/context memory. Thus different wrappers over the same shared provider can fail the exact memory identity predicate before any original installation.

`TrackedCpuMemory` is sealed, owns a readonly inner memory and forwards every GPU-used read/write/mapping/watch/publication capability. Its distinct behavior is CPU-thread `LastFailure` bookkeeping; GPU, AGC and command stream code do not consume `ITrackedCpuMemory`/`LastFailure`. It now explicitly opts into a neutral `ICpuGpuMemoryView` contract. Generic `ICpuMemoryWrapper` does not opt in. This preserves decorators that affect GPU-visible behavior or capabilities.

Both presenter attachment and command stream binding use the same bounded resolver. It returns one chosen exact reader/provider, rejects null/cyclic/over-bound or changing explicit links, and does not copy bytes or query mappings. The usual readonly tracking link requires no allocation. A bound Metal backend retains its first exact resolved memory and rejects a later different view before creating a host/worker, returning an existing queue or enqueueing. Presenter attachment still replaces a truly different root as before, so existing original exact-identity checks refuse it. No presenter `ReferenceEquals`, original mapping/watch, native ownership or lifetime predicate is relaxed; no original is recaptured.
