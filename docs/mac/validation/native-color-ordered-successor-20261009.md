# Native selected-color pending-successor ordering

This successor preserves `020d462d` and its failed completed-predecessor evidence. The first actual same-command-buffer color case passed its full 2MiB native oracle; the completed-predecessor row then refused sampled consumer sequence2 because the sibling inventory treated its later pending producer sequence3 as an immediate overlapping writer.

The production exception is limited to that ordered relationship. The currently taken work must also be the currently executing work, have a readonly sampled lease and retained queued dependency on the exact prior producer, and run in the same logical queue. The later node must still be pending, have a later sequence, be the exact accepted unencoded native-color producer, and retain the same prior as its predecessor. Original source, memory, session, placement, protected token and complete physical mapping segments/incarnations must match. A stale, earlier, taken, encoded, foreign-queue, unretained or unrelated writer still refuses. All other target, storage, buffer, depth, live native owner and retirement inventory checks remain strict.

The exception does not clone the source or make a retain immutable. The existing image/texture may be reused by the successor. The earlier consumer must encode before that successor in the actual retaining native queue; the existing exact handle/version, same-command-buffer or real status4, protected token and original watch checks still govern the borrow. After a successor changes the image version, an old receipt remains invalid.

Ten added managed rows use actual public Submit/Take queue metadata with explicitly synthetic mapping outcomes. They test the ordered case and missing execution, foreign queue, earlier sequence, taken/encoded successor, missing predecessor, stale mapping, differing physical projection and differing original token. They explicitly assert no encoded producer, native handle or completed sequence; they are not GPU/content positives.

The existing completed-predecessor required-device fixture now uses an actual argument-buffer fragment shader that reads all 512×512 prior RGBA16Float pixels into an independently owned transient target before the partial-mask successor. A real completed blit compares every output half component against the original [.25,.5,.75,1]. The same fixture separately compares the successor's complete output [.875,.5,.75,1] and original guest allocation bytes. Constant-shader binding alone is no longer called a GPU read oracle.

The controlled predecessor-cleanup fixture uses two independent address-zero CPU-seeded temporary native textures, avoiding a simultaneous taken read/write alias of the original attachment. Both actual temporary owns must be released even when the first release reports failure; the original predecessor refusal remains primary, no work is acknowledged, and cleanup uncertainty remains quarantined. A saved/restored `GpuFatal.OnFatal` reporting hook allows that expected failure to be asserted instead of terminating the worker; positive cases require no reports. Restoration occurs after native-state cleanup.

All new source controls are prepared only. No build, device worker, game, source promotion or gameplay claim is part of this checkpoint. Original `020d462d`, the aborted row and its source/DLL evidence remain preserved.
