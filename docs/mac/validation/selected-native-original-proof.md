# Original selected native-owner proof checkpoint

This isolated source checkpoint extends the original one-use mapped CPU seed
through accepted native storage ownership. It is unbuilt and unexecuted. The
cached `SHARPEMU_METAL_SELECTED_NATIVE_REUSE=1` policy is off by default; graph
provenance remains `Stable=false`, and the graph path keeps its strict policy.

The original source, complete native-protected tracker token/read observation,
mapping capture and physical write watch are captured before the owned CPU copy.
They are transferred only at exact successful native-image publication. The
selected key, association reference, presenter session, attached memory, texture
handle and content version remain exact. Successful known compute stores advance
only a private native version and producer sequence. They never refresh an epoch,
token, mapping receipt, physical watch or source identity. Later consumers require
the earlier producer acknowledgement and the same native command queue.

The provider watch retains at most 128 original owners, each with at most 64
immutable canonical physical runs. Installation excludes participating writers;
writer admission precedes overlapping watch revocation and destination bytes.
Completed disjoint writes leave the watch valid without replaying bounded history
or restamping its baseline. Active writers, overlap, unknown completion, saturated
bookkeeping, retired/replaced mappings and closing backing decline. Exact watch
release consumes its own slot before reuse. Only optional watched copies allocate
a finalizable bookkeeping owner; ordinary mapping-copy captures do not.

The watch is forwarded through actual Mac host views, SharedBackingViews,
GuestSpaceOwner, PhysicalVirtualMemory and TrackedCpuMemory. It retains neither a
pointer nor a long-lived alias pin. Mapping currentness and watched currentness
remain conservative bounded vetoes, not retained mapping leases. Native protection
coverage is separately required; ManagedWriter-only tracker coverage cannot earn
the native reuse exception. No fault handler, permission repair or retry changes.

Participating ordinary aliases are covered by the existing destination write
intervals. Raw/JIT/native alias stores which bypass those intervals and the
protected virtual tracker remain uncertified. Tracker notification precedes the
resumed store, so equal metadata is not a write-completion or safe-point receipt.
This opt-in checkpoint cannot establish general guest content authority and must
not be promoted from managed-only success. Selected GPU bytes remain native-only;
the implementation neither retile-publishes guest RAM nor enables address-only
aliases or arbitrary sampled views.

Prepared controls are 17 managed read-watch rows over owned pinned arrays and
six actual-Mac/SharedBackingViews-to-Metal fresh-worker Fact rows; the fixture's
memory wrapper forwards the real views directly, so these rows do not separately
qualify the PVM/Tracked forwarding. The native positives call actual
SubmitComputeDispatch and DrainGuestWorkCore for seed upload, translated MIMG
store, unrelated canonical allocation/protection/free, translated load and a
second store. They compare every selected native texel and every guest byte,
require actual command status 4, and prove the original mapping/token/epoch remain
unchanged. Readonly first use has its own positive. Negatives use a participating
physical alias write, managed CPU write, same-address remap ABA and presenter
session reset; no stale CPU fallback is allowed.

Each device Fact requires a separately granted fresh worker, actual architecture
assertions, `SHARPEMU_TEST_REQUIRE_DEVICE=1`,
`SHARPEMU_TEST_REQUIRE_SELECTED_NATIVE_REUSE=1`, the policy enabled, and the shared
machine lock. A bounded outer worker must terminate on unknown native completion;
the fixture quarantines native handles rather than freeing beneath pending GPU
work. No device execution, game advancement, performance or PS5 topology claim
has been made from this source checkpoint.
