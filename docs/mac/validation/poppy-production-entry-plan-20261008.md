# Poppy: smallest production store-continuation increment

Source-only plan based on main `059eced3`. No code, configuration, recovery policy, build or game change accompanies it. The goal is passing the actual entry fault at guest RIP `0x80135FB0B`, bytes `C4 C1 7D E7 04 16`; gameplay remains unqualified.

## Existing evidence and reusable code

The preserved concurrent-store experiment shows why accepting only Armed→Invalidating is insufficient: legitimate queued faults arrive after another handler has restored RW and published Disarmed. Its decline-Disarmed controls fail for temporal stores as well as VMOVNTDQ. This does not authorize unconditional retry.

The directory-lock reruns of the single-step/store-retirement experiments passed nine fresh Rosetta processes. The exact store can return from its write fault, execute, deliver an owned next-PC trace trap, execute a same-thread handler SFENCE, and retire the diagnostic count. Three 32-thread retirement cases checked all owned bytes. Allocations remained immutable until joins; these are not provider lifetime or CLR signal-chain proofs. Evidence: `artifacts/validation/all-games-20261008/poppy-rosetta-single-step` and `poppy-rosetta-store-retirement`; see `poppy-store-continuation-probe-20261008.md`.

Preserved provider checkpoint `696f7a3a` in `agent-cpu-poppy-permission-cohort` supplies useful ordinary code: `MacHostMemory.TryCreateTrackedImageProtection`, `HostMappedCopyLedger.TrackedProtectionCohort`, `MacHostViews.ApplyTrackedProtection`, actual mprotect/immediate errno, `HostNativeViewDomain` plus backing pins, and provider-owned `MacOwnedStoreFence`. It is unbuilt/unrun. `TryRestoreForStore` allocates a continuation and takes `HostViewRegions.Gate`; `MacStoreContinuation.TryRetireAt` also takes that gate. None may be called from a signal handler. `GuestImageWriteTracker.TryEnrollCanonicalProtectionCohort` has no production caller and requires prior guest/fault-callback quiescence.

## Implementation order

1. **Publish exact native authority on ordinary paths.** Reuse the retained View/domain bookkeeping, but export a fixed native receipt containing original mapping/domain identity, backing pin, full measured kernel-page footprint, authoritative guest base rights, protection epoch, and actual successful RW restoration state. Enroll all tracker/PageGuard obligations covering that kernel page before it is armed. Guest readonly, overlapping foreign obligation, partial cohort, missing identity and saturation decline. Publish pending revocation before `GuestGpuMemory.Register` and `NoteProtected` call `_pages.Permissions.Set`, as well as before rearm, retirement, raw mapping/protection and backing close. Drain outside provider/PVM/GSO gates before native mutation. Unknown outcomes retain exclusion; they do not reopen an old epoch. The provider's last successful guest-right record alone cannot cover the Permissions.Set→syscall gap.

2. **Install a bounded native cell before each guest executor enters.** Use actual entry/exit scopes in `DirectExecutionBackend` and `DirectExecutionBackend.NativeWorker` (including the `GuestThreadExecution.EnterGuestThread` paths), not lazy handler TLS. The process-retained cell records native thread/session, exact receipt/one-use ticket, store PC, next PC, original TF and pending state. One outstanding continuation per thread is enough for this finite increment; nested/missing/foreign cells refuse. Allocate and warm every native routine before signal installation/guest entry. Worker exit and missing trap quarantine pending ownership rather than releasing it optimistically. No managed allocation, monitor, interface dispatch or unprepared CLR call is allowed in the handler closure.

3. **Add the exact fault and trap routes.** In `PosixFaultBridge`, process the owned finite store route before `TryHandleTrackedImageWriteFaultForInvocation` and the generic GPU fast path. Validate actual write-fault classification, authenticated saved frame, exact instruction bytes (through a safely enrolled executable-code identity), clear preexisting TF, overflow-safe R14+RDX, the entire 32-byte write and exact next PC. Acquire the original native domain/backing/permission ticket before actual restoration, publish the actual RW receipt, then set saved TF and return. A queued same-cohort writer may use the same successful RW receipt only while its original epoch/domain/right obligations remain pinned; Busy or Disarmed is never authority by itself.

   Handle SIGTRAP before the generic bridge converts every trap to breakpoint code `2147483651`. Only the cell's owned trace classification, native thread/session and exact next PC qualify. Execute the eagerly prepared same-thread native SFENCE, clear only the TF this route installed, consume the exact ticket once, and release after the fence. Unrelated debugger/breakpoint/user traps follow the previous action/shared recovery chain unchanged. Wrong PC, nested fault, unknown restoration or foreign trap retains/quarantines the ticket. Do not call the ordinary `MacStoreContinuation` wrapper here.

4. **Connect tracker invalidation without inventing completion.** Record affected tracker content generations before admitting the retried write; an existing dirty flag must not coalesce away a later notification. Keep pending native-store ownership separate from dirty/currentness metadata. CPU copies, GPU publication, rearm and physical reuse cannot treat that metadata as completed bytes while a ticket remains. The actual trap/fence is the store-retirement boundary, not the first fault-handler return.

## Required qualification before a game

First qualify the ordinary provider prerequisite on real owned Mac mappings: actual RO→RW receipt, guest-RO rejection, exact full kernel-page cohort, current/queued same-owner tickets, close/remap/base-right/rearm exclusion, unknown failure retention and full neighbor bytes. Constructed frames are useful negatives but cannot qualify signal activation.

Then run fresh actual Rosetta/CLR workers through the real `PosixFaultBridge`, with measured kernel/provider geometry, actual architecture/runtime assertions and full byte oracles. Minimum cases are: exact single-thread VMOVNTDQ; 32 queued writers; concurrent attempted remap/close/base revocation/rearm; overlapping tracker owners and 4KiB-to-16KiB cohort refusal; preexisting TF/unrelated SIGTRAP chaining; wrong-next-PC/nested fault and worker-exit quarantine. Confirm the actual fault→sigreturn→store→trap→SFENCE order and zero released pins only on proven success. No instruction skip, unconditional Disarmed acceptance or generic retry follows from the standalone probes.

Only after those receipts pass should a separately granted signed Poppy replay enable this finite route and report the reached scene. Keep other instruction forms and unsupported cohorts on the current failure path. This plan provides no shader-cache/performance change and no guarantee of later gameplay/rendering correctness.
