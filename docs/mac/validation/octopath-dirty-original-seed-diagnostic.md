# Octopath dirty flag versus original typed seed

This diagnostic-only checkpoint is based on ab9dedeb. It is isolated from the unbuilt full 4 MiB RGBA8 publication candidate. `SHARPEMU_TRACE_GUEST_IMAGE_DIRTY=1` enables at most 64 ordinary before-consume records. Default off returns before presenter/tracker locking and formatting. No dirty consumption, upload, writer admission, recovery, native permission or GPU publication policy changes.

Before the existing ConsumeDirty call, the presenter captures the exact current image's retained original seed origin, image version and session under its gate, releases that gate, then observes tracker metadata. It never queries the tracker while holding the presenter gate. It records original/current protected and watch identities, generations and byte extents; original Observed flag, physical footprint, mapping epoch, original/current session, image version, current dirty bits and arm epoch. The global current mapping epoch is a separately sampled scalar, not a native query or mapping lease. The original values are not rebased or refreshed.

Equality can show that the retained dirty flag corresponds to a generation already observed by the seed. Inequality shows a tracked generation/owner change. Neither proves raw/JIT writer exclusion, write completion, full CPU replacement, atomic event ordering, nor authorizes acknowledgment. No acknowledgment is added. A newer write can race these observations or consumption. The 64-record prefix can exhaust; absence is not evidence of no writes.

When enabled, the existing first-fault per-arm record also retains its scalar invocation before publishing FirstCpuWriteSeen=2; positive identifies a correlated native callback, zero a managed notification and -1 an unpublished record. No formatting, allocation, new locks or clock calls are added to that signal capture. Existing lifetime tracing retains its original timestamps and pending log behavior. A first callback precedes the resumed store and is not a completion receipt.

Source reviewed and frozen separately before any build/run. Existing typed CPU synchronization controls remain the appropriate regression suite; this checkpoint has not been executed and makes no game-fix claim. A future conditional dirty acknowledgment must retain exact image/session/version and original mapping/content observations and cannot consume a newer generation.
