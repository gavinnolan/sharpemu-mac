# Canonical R32Float singleton storage array and blocked Sint prerequisite

This proactive backend qualification is based on root f48e7b4e. Current game evidence captured only RGBA8 and R32Uint arrays; no game descriptor, title progression or frame-rate improvement is claimed for the added Float class or deferred Sint class.

The pinned [AMD PAL IMG_FMT enum](https://github.com/GPUOpen-Drivers/pal/blob/c5e800072a32f68b6ccc4422936d96167c6e0728/src/core/hw/gfxip/gfx9/chip/gfx9_plus_merged_enum.h#L5253) defines R32Uint=0x14, R32Sint=0x15 and R32Float=0x16. The existing exact unified decoder maps21 to data4/number5 and22 to data4/number7; Metal maps these to R32Sint54 and R32Float55 with four bytes per pixel. This patch changes neither table nor shader numeric interpretation.

Admission adds only the Float alternative: matching complete raw8 descriptor/unified22, shader Float storage class, X001 selector0x204 and exact PERF_MOD7 word0x00700000. Existing RGBA and Uint conditions remain unchanged. Shared guards still require native2DArray type13 even with one layer,1x1/pitch1, resource and selected mip0, layer/base-array0,64KiB-aligned nonzero address, no metadata/compression/unknown flags, matching array/storage compiled shape, and known non-atomic access. No all-format range, flattening or fallback is introduced.

The physical layout uses the existing independent [32bpp mode27 AddrLib origin fixture](../../../tests/Fixtures/R32UintSingletonArray/README.md):64KiB block/slice, origin byte0, one addressed texel. Numeric interpretation does not change the32-bit physical footprint. This only qualifies the origin of the exact admitted block; it is not PS5 topology or arbitrary tiled-offset proof. Snapshots still own the full physical read and detached four-byte linear seed before native materialization.

Managed controls exercise the production snapshot and storage-format/layout methods, exact finite float bits, detached raw/data ownership, missing/short/unstable payload rejection, wrong live numeric format, and near-miss raw/compiled fields before guest reads. Existing tests also cover the unchanged RGBA8 and R32Uint classes. No new public or friend contract is added.

Four Float native fixtures are compile-only until a serialized required-device grant: valid store, out-of-range X, out-of-range layer and negative layer. Each calls actual snapshot→EnsureStorageImage, checks native type/array length/format/usage and exact seed bits, executes translated Gen5 MIMG store/load, and compares physical bits and all four logical channels. Float seed -19.25f and stored3.140625f are finite, exactly representable. X001 ONE is Float1.0 bits0x3F800000, never an integer ONE bitpattern. All65532 guest-neighbor bytes remain unchanged; snapshot mutation proves detached ownership. Native view and shader libraries release before registry texture cleanup.

The load-only fixture explicitly creates a native sampled X001 view, as in the already qualified Uint fixture. It does not qualify production sampled-view binding, cross-queue coherence, Drain/Compute dispatch integration or dormant source-graph activation. No actual AMD hardware oracle is claimed; the shared format enum, existing addressing fixture and explicit numeric expectations are independent of the tested translator.

The first combined proposal built successfully and passed115 managed controls on ARM, but its compile-only native fixture selection failed4 Sint cases (12/16 passed). This exposed a real shared normalization prerequisite: ResourceMaterializer deliberately maps write-only R32Sint storage to Uint and rejects other signed storage. Metal R32Sint54 requires compiled Sint, so simply weakening the assertion or binding that uint shader to a signed texture would be incorrect. The unsupported Sint admission and synthetic signed expectations were removed from this shipping slice; failed logs/TRX and the original source/patch remain retained in the evidence archive. No shared capability or default/Vulkan semantics were changed. R32Sint remains blocked pending a separately reviewed native signed-storage normalization capability, cache-policy isolation and actual normalized MIMG numerical proof.
