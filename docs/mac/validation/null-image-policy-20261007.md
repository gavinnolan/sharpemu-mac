# Normalized null image policy, 2026-10-07

An undecodable descriptor becomes an intentional null only when **every resource word is zero**. A zero base address alone is insufficient. The normalized frontend now preserves copied resource words and actual compiler shape/access and creates a fresh zero RGBA8 resource only for a read-only, non-array, single-mip 2D float sampled or storage binding. All four channels are zero; the old Format0 / alpha255 placeholder was not this contract.

Writable and atomic null storage are explicitly unsupported for both decoded zero-address and undecodable all-zero resources. A writable native dummy would retain stores, while null stores must be discarded. No shared image at address0 can carry writes into another null binding. Unknown intent, unknown dimension/resource class, integer, array/cube/volume/1D/MSAA/depth/dynamic-mip/R128 null shapes are rejected by the undecodable-null path until separately qualified. Existing typed decoded-null read materialization remains a distinct path; these tests do not broaden its qualification.
