# Native storage-image layout checks, 2026-10-07

Storage allocation now decodes guest **texture** formats, rather than falling back from the render-target table to RGBA8. R16 seeds use 2 bytes per texel, RG32 integer seeds use 8, and RGBA32 integer seeds use 16. Block-compressed, unknown, unsupported extent, array/volume and multi-mip storage views fail explicitly. Deferred retained tiled seeds are prepared before upload; incomplete, unstable or absent new-image seeds cannot initialize an image. Existing images must match actual native format and extent and be initialized. Allocation ownership is released if upload throws.

Evidence: 37 managed ARM64 cases passed (16 storage-format/materializer cases, 11 writer-admission cases and 10 retained queue-snapshot cases). Before the extent followup, 34 managed cases also passed under Rosetta. Managed cases invoke the real `EnsureStorageImage` rejection and existing-image lookup paths with no device, plus the actual layout helpers.

Two actual ARM64 Metal readbacks passed under the shared exclusive game/device lock: production `EnsureStorageImage` allocation/upload for R16Float (guest 2/7) and RG32Uint (11/4), width 3, height 2, pitch 5. Independent sentinel bytes occupied both rows and the final row omitted trailing padding; native texture bytes matched every texel. This proves native allocation/upload and byte layout, **not** shader storage execution, numeric class conversion, live-image freshness, gameplay or source-graph correctness.

The device source was commit `7808c5f` plus the dormant registry exception-safety worktree patch with SHA256 `94106c5a509a95f2752ca057142dbf74a6604f18b6dbd9e1eb33815d69487aa5` (materialize/validate all leases before retain counters, preflight/rollback duplicate capture). The storage fixtures do not enter those registry paths. It was a dirty source build and must not be labeled an exact clean-commit test. Logs: `/tmp/sharpemu-metal-storage-device-final.log`, `/tmp/sharpemu-metal-storage-format-extents-arm.log`; the precise patch is `/tmp/metal-storage-device-registry-diff.patch`, copied by the integrator into durable evidence.

A genuine null descriptor is a separate contract: compute only calls `EnsureStorageImage` for nonzero guest addresses. The normalized frontend's old failed-decode branch still needs typed-null normalization and must never convert a nonzero invalid resource to fabricated texels. The source graph remains inactive; initialized live-image reuse is not newly qualified by these layout checks.
